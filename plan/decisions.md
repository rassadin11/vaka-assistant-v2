# Принятые решения

Единственное место, где записаны решения проекта — архитектурные, продуктовые и процессные. Остальные документы на них ссылаются и не повторяют их.

Правила ведения:

- **Одно решение — одна запись**: дата, суть, причина, где подробности. Детали реализации остаются в спеке или справочнике, сюда — только то, что решено.
- **Новое решение — новая запись или правка записи с датой правки.** Отменённое решение не удаляется: помечается «отменено ДАТА → D-NN», чтобы была видна причина прежнего устройства.
- **Решение принимается здесь до кода**, как и любое отклонение от плана (регламент в [CLAUDE.md](../CLAUDE.md)).
- Открытые вопросы сюда не пишутся — они в [roadmap.md](roadmap.md). Номера «№N» — сквозная нумерация отложенных обсуждений, на неё ссылаются файлы этапов.

Собрано 2026-10-18 из блока «Принятые архитектурные решения» мастер-плана, списка отложенных обсуждений, `plan/progress.md`, спек и справочников. Если решение найдено где-то ещё и не попало сюда — перенести, а в источнике оставить ссылку.

## Архитектура и данные

- **D-01. Multi-tenant с изоляцией через RLS** (2026-07-09). Один пул воркеров на всех пользователей, изоляция данных — PostgreSQL RLS по `user_id`; per-user контейнеров нет. RLS-шаблон, роли и PK — [db-schema.md](db-schema.md).
- **D-02. `SET LOCAL app.user_id` на каждую транзакцию, четыре роли БД** (2026-07-09). Session-level SET запрещён: в профиле `prod` протекает через PgBouncer в transaction mode. Роли: `migrator` (владелец таблиц, только Alembic), `app` (рабочая, не владелец — иначе RLS обходится), `service` (BYPASSRLS — шедулер, outbox, админ-команды), `metrics_ro` (только агрегаты для Grafana, 2026-07-12).
- **D-03. Первичные ключи** (2026-07-09). uuid v7 (генерация на приложении) для сущностей вне аргументов модели; bigint identity для model-facing сущностей и логов — DeepSeek надёжнее воспроизводит короткие числа, чем uuid.
- **D-04. Состояние только в хранилищах** (2026-07-09). Postgres / Redis / S3; gateway и воркеры stateless.
- **D-05. Тонкий gateway** (2026-07-09). secret_token → дедуп → rate limit → enqueue → ответ за <100 мс; Postgres в горячем пути нет, статусы пользователей проверяет воркер.
- **D-06. Очередь — Redis Streams** (2026-07-09). Партиционирование по пользователю, две очереди: interactive и background.
- **D-07. Схема БД зафиксирована** (2026-07-09, обсуждение №1). Схема — [db-schema.md](db-schema.md); изменения — правкой этого файла до миграции. Enum-поля — `text` + `CHECK`; все времена — `timestamptz` (UTC); FK `user_id ... ON DELETE CASCADE` как механика удаления по GDPR. Миграции обратно совместимы с предыдущей версией кода (expand-contract).
- **D-08. Пользовательские OAuth-токены — в Postgres с envelope-шифрованием** (2026-07-09). Ключ в vault; vault — только для конфигурационных секретов сервисов. OAuth вместо приёма паролей.
- **D-09. Эмбеддинги локальные, модель multilingual-e5-large** (2026-07-10, обсуждение №4). Мини-бенчмарк на русском: recall@5 0.929 против 0.893 у bge-m3. Инференс — отдельным внутренним сервисом, а не в каждом воркере. В профиле `small` эмбеддингов нет — см. D-21.
- **D-10. Бюджеты пользователя — в рублях в день, а не в токенах** (2026-07-11). Деградация ступенями по мере расхода. Числа — [pricing-draft.md](pricing-draft.md) и `core/profile.py`.

## LLM и промпт

- **D-11. LLM — через OpenRouter за интерфейсом `LLMProvider`** (2026-07-09). Тесты — только `MockLLMProvider`, в сеть не ходят. Prompt caching через статичный префикс.
- **D-12. Политика данных LLM: `data_collection: deny` и allowlist провайдеров** (2026-07-09). Исключаются провайдеры, обучающиеся на данных или хранящие их для обучения (включая официальный DeepSeek API). Причины: в контекст попадают финансы, письма и события календаря; Google Limited Use запрещает передачу данных Workspace API для обучения; передача LLM-провайдерам раскрывается в privacy policy.
- **D-13. Базовая модель — `deepseek/deepseek-v4-flash`** (2026-07-15). Eval пройден, модель ~2.2× дешевле V3 ([pricing-draft.md](pricing-draft.md) §2a). Allowlist fp8-провайдеров: `novita` (primary) + `parasail` (fallback при 429). Модель задаётся env `OPENROUTER_MODEL`; **кодовый дефолт `DEFAULT_OPENROUTER_MODEL` по-прежнему `deepseek/deepseek-chat`** — флип в коде не сделан, на живой установке модель задана env.
- **D-14. Смена базовой модели — только через прогон eval-набора** (2026-07-15, уточнено 2026-10-17). Второго текста промпта не требуется (D-15). Порог eval вычисляет `evals/prompt_eval.py` как `ceil(0.9 × N)`.
- **D-15. Статичное ядро промпта одно на все модели** (2026-10-17). Отменена схема «текст на модель» (`v1` для deepseek-chat, `v2-flash` для flash, связка `prompt_version_for_model`): каждое правило писалось дважды и проверялось двумя прогонами, а дефолт в коде оставался слабым `v1`. Единственное ядро — текст `v2-flash` под именем версии `v2`. Реестр `PROMPTS` и запись `prompt_version` в messages/usage остаются. Model-specific форк допустим только новым решением. Спека — [system-prompt-spec.md](system-prompt-spec.md).
- **D-16. Голосовые — Groq whisper-large-v3** (2026-07-11, обсуждение №6). ~$0.11 за час, латентность в разы ниже локального CPU-инференса. Код изолирован интерфейсом `STTProvider`, переход на локальный faster-whisper — дешёвая замена провайдера.

## Развёртывание и инфраструктура

- **D-17. Юрисдикция закрытой беты — всё за рубежом, осознанный риск** (2026-07-15, обсуждение №3 в части юрисдикции). OpenRouter режет РФ по региону аккаунта и IP, поэтому рабочая связка — не-РФ аккаунт + не-РФ IP сервера; релей не нужен. **Долг**: локализация по 152-ФЗ (primary Postgres в РФ) обязательна к публичному запуску для РФ-аудитории — отдельная миграция; юр-заключение — до паблика. Хостингом не снимается: уведомления РКН о трансграничной передаче и об обработке, согласие и раскрытие. Открытая часть №3 — в [roadmap.md](roadmap.md).
- **D-18. Два профиля развёртывания на одной кодовой базе** (2026-09-06). `prod` (16 ГБ) и `small` (2 ГБ, закрытый круг), выбор — `DEPLOYMENT_PROFILE=prod|small`, каждый флаг перекрывается своей env-переменной. **Инфраструктуру режем, код не режем**: форк запрещён — одни тесты, один eval-набор, правки ядра идут в оба профиля. Отличия `small`: без Infisical, PgBouncer, мониторинга, Caddy для webhook и локальных эмбеддингов; один Redis `noeviction` с TTL на кэш-ключах; polling; полнотекстовый поиск вместо векторного; whitelist `ALLOWED_TELEGRAM_IDS`. Схема БД и миграции общие. Подробности — [small-profile.md](small-profile.md).
- **D-19. Прод на 16 ГБ выведен из эксплуатации; живая установка — `small`** (2026-10-16). Указание владельца: «сервер на 16 ГБ больше не актуален». Живой сервер — `31.77.203.98`, бот @vAssistantv2testbot (решение 2026-10-15), данные прода перенесены целиком (решение 2026-09-06, выполнено 2026-10-15 — S18), все 44 пользователя внесены в whitelist. Профиль `prod` остаётся в коде и compose-файлах, не развёрнут; его рунбук — [docs/archive/runbook-deploy.md](../docs/archive/runbook-deploy.md).
- **D-20. Mini App на малом сервере, не дожидаясь 3 ГБ** (2026-10-16). Повод — D-19. Наружу открыты SSH, 80 и 443; Caddy с одним маршрутом `/app/*` и TLS Let's Encrypt.
- **D-21. Поиск в `small` — полнотекстовый Postgres** (2026-09-07). Генерируемая колонка `tsvector` + GIN; векторные колонки остаются в схеме обоих профилей. Флаг — `RETRIEVAL_BACKEND=vector|fts`.
- **D-22. Лимиты на напоминания и подобное в `small` сняты** (2026-09-06). При малом числе пользователей не нужны; структурные потолки остаются числами, но поднятыми. Значения — `core/profile.py`, обоснование — [small-profile.md](small-profile.md) §5.
- **D-23. Бэкапы `small` временно только локальные** (2026-10-15). `BACKUP_ALLOW_LOCAL_ONLY=1` до появления внешнего хранилища; адресат — решение владельца (бесплатных вариантов достаточно). Открытый пункт — в [roadmap.md](roadmap.md).
- **D-24. Секреты** (2026-07-09, уточнено 2026-09-06). Только вне репозитория: в `prod` — Infisical self-hosted, в `small` — env-файлы с правами 600 на сервере; `.env` в репозитории запрещён.
- **D-25. Telegram: polling в dev и `small`, webhook в `prod`** (2026-07-09, уточнено 2026-09-06). Путь обработки апдейтов общий.
- **D-26. Решения контура `prod`, который сейчас не развёрнут** (2026-07-15/16). Ansible-провижининг с тестом через Molecule-в-CI; секреты через Infisical, Ansible держит только bootstrap-vault; деплой CI → GHCR → сервер. Подробности — [archive/stages/stage-1.md](archive/stages/stage-1.md).

## Продукт и поведение бота

- **D-27. Mini App — отдельный сервис `webapp/`** (2026-07-17, этап 9). FastAPI отдаёт статику фронта и JSON API, gateway остаётся тонким. Auth — валидация `initData` + короткоживущий токен сессии; все запросы к БД — через `user_transaction` под RLS. Общая доменная логика — в `core/`, чтобы инструменты LLM и API использовали один код. Палитра — спокойная коричнево-белая, без ярких акцентов (2026-07-17). Подробности — [archive/stages/stage-9-architecture.md](archive/stages/stage-9-architecture.md).
- **D-28. Ручного одобрения заявок нет** (2026-07-18). Новый пользователь сразу `active` и выбирает город; легаси-pending автоактивированы; `/approve` и `/pending` удалены, `/reject` остался. В `small` вход дополнительно режет whitelist (D-18).
- **D-29. Всё связанное с Google пока пропускать** (2026-07-10). 4.7 (OAuth, календарь, почта) не начат; критический путь — домен → privacy policy → заявка Google (обсуждения №5, №10 в [roadmap.md](roadmap.md)).
- **D-30. Часовой пояс меняется словами и командой; напоминания следуют за пользователем** (2026-07-20). Инструмент `set_timezone` и команда `/timezone` как детерминированный запасной путь. Повторяющиеся напоминания пересчитываются в текущей `users.timezone` на каждом срабатывании, колонки таймзоны у `scheduled_tasks` нет. Подробности — [../tools_registry_v1.md](../tools_registry_v1.md) §7b.
- **D-31. Персона ассистента** (2026-07-18). Опциональные имя, обращение и стиль через инструменты set/clear, хранение в `users.assistant_profile`. Итерация 2 — грамматический род (статус — [progress.md](progress.md)). Спеки — [archive/iterations/](archive/iterations/).
- **D-32. Тематические заметки — отдельная сущность** (2026-07-31). Память фактов — для атомарных фактов с автоинжектом; накапливаемые записи одной темы — в `notes`, без автоинжекта, с явным чтением инструментами. Переполнение: мягкое предупреждение с 90 %, жёсткий отказ на 101-й заметке, авторевизия только с явного согласия, молчаливого вытеснения нет. Подробности — [../tools_registry_v1.md](../tools_registry_v1.md) §7c.
- **D-33. Экран «Заметки» в Mini App** (2026-10-15). Полный CRUD; переименование в занятую тему — честная ошибка без слияния; оптимистичная блокировка по `updated_at`; плоский текст без рендера Markdown. Спека — [specs/miniapp-notes-spec.md](specs/miniapp-notes-spec.md).
- **D-34. PDF: подсказка про точечные вопросы** (2026-07-17). На просьбу пересказать весь файл ассистент подсказывает, что точечные вопросы работают лучше (RAG по чанкам); явная просьба о суммаризации — первые ~30k токенов одним проходом.
- **D-35. Регулярные агентные задачи включаются словами, есть разовый запуск** (2026-10-17). Спека — [specs/recurring-agent-tasks-spec.md](specs/recurring-agent-tasks-spec.md).
- **D-36. Общие объекты — сначала часть 1: друзья и общие напоминания фан-аутом** (2026-10-18). Общие заметки — отдельной частью 2. Реализация части 1 ждёт обсуждения №12 и закрыта флагом `FRIENDS_ENABLED=0`. Спека — [specs/shared-objects-spec.md](specs/shared-objects-spec.md).
