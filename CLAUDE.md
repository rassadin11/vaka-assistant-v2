# Проект: Telegram-сервис персональных ассистентов

Multi-tenant сервис: один бот, общий пул воркеров, изоляция пользователей через PostgreSQL RLS. Стек: Python 3.12, FastAPI, aiogram 3.x, asyncio-воркеры, PostgreSQL 16 (+pgvector), Redis, Alembic, Caddy; LLM — через OpenRouter. Живая установка — профиль `small` (2 ГБ, polling, без PgBouncer/Infisical/мониторинга); профиль `prod` остаётся в коде, но не развёрнут — см. [docs/architecture-overview.md](docs/architecture-overview.md).

2. **Задача по фиче**: её спека в [plan/specs/](plan/specs/) целиком, включая DoD. Спеки нет — сначала написать её.
3. **Инструменты**: разделы 1–3 из [tools_registry_v1.md](tools_registry_v1.md) + целевой раздел инструмента.
4. **Системный промпт и контекст-менеджер**: [plan/system-prompt-spec.md](plan/system-prompt-spec.md).
5. **Всё про БД**: [plan/db-schema.md](plan/db-schema.md).
6. **Развёртывание и эксплуатация**: [plan/small-profile.md](plan/small-profile.md) + [docs/runbook-small.md](docs/runbook-small.md).
7. **Лимиты**: числа — в `core/profile.py`; тарифная сетка — [plan/pricing-draft.md](plan/pricing-draft.md) (черновик до 7.4).

Архив (`plan/archive/`, `docs/archive/`) — снимки на дату; читать только по прямой ссылке, когда нужна история решения.

## Регламент (нарушение = брак)

- **Отклонение от плана — сначала правка планового файла, потом код.** Решение — записью в [plan/decisions.md](plan/decisions.md); детали фичи — правкой её спеки; схема БД — правкой db-schema.md. Если в плане нет ответа на возникший вопрос — остановиться и дописать план, а не решать молча в коде.
- **Приёмка любой задачи**: тесты зелёные + ручной e2e-сценарий + отсутствие секретов в диффе (gitleaks) + для инструментов — запись появилась в tool_calls_log. Где есть batch-обработка — отдельно убедиться, что обрабатывается весь батч, а не первый элемент: это типовой источник брака, ловленный дважды.
- **После приёмки**: одна строка в [plan/progress.md](plan/progress.md) (дата, коммит); подробности приёмки — что проверено, что найдено — в сообщение коммита; выполненный пункт уходит из [plan/roadmap.md](plan/roadmap.md).
- **Документы правятся по D-38**: один факт — одно место, остальные ссылаются; живое и архив — разными директориями; индексы без фактов. Ссылки и индексы проверяет `tests/test_docs.py`.
- **Не реализовывать** пункты из «Отложено» в [plan/plan-improvements.md](plan/plan-improvements.md) без явного решения.

## Инварианты кода (проверяются на каждой задаче)

- Состояние только в Postgres/Redis/S3; gateway и воркеры stateless.
- RLS: каждая транзакция под ролью `app` открывается с `SET LOCAL app.user_id`; session-level SET запрещён (в профиле `prod` соединения идут через PgBouncer в transaction mode — код обязан работать в обоих профилях). Роли: `migrator` (только Alembic), `app` (рабочая), `service` (BYPASSRLS, только кросс-пользовательские процессы).
- `user_id` никогда не приходит из аргументов LLM — только инжект диспетчером из TaskContext.
- Mutating-инструменты идемпотентны при переигровке (реестр §1.7, ключ `idem:{update_id}:{n}`).
- Тесты не ходят в сеть и не тратят токены: MockLLMProvider / MockSTTProvider.
- Секреты — только вне репозитория: в профиле `small` — env-файлы с правами 600 на сервере, в `prod` — Infisical (кроме bootstrap.env); `.env` в репозитории запрещён.
- LLM только через интерфейс LLMProvider; OpenRouter с `data_collection: deny` и allowlist провайдеров из конфига.
- Время: в БД `timestamptz` (UTC); для модели — ISO 8601 в таймзоне пользователя; `users.timezone` всегда явная.
- Миграции обратно совместимы с предыдущей версией кода (expand-contract).

## Конвенции

- Код, идентификаторы, docstrings — английский; тексты для пользователей и плановые документы — русский.
- Монорепо: `gateway/`, `worker/`, `core/`, `tools/`, `webapp/` (backend Mini App), `miniapp/` (frontend Mini App), `embeddings/`, `migrations/`, `infra/`, `tests/`, `evals/`; обзор — [docs/architecture-overview.md](docs/architecture-overview.md).
- Контракты между этапами (envelope очереди, ToolDefinition, LLMProvider) — pydantic-модели в `core/`; менять только с правкой плана.
- Ожидаемые команды после этапа 0–1: `make dev-up` (окружение с нуля), `pytest`, pre-commit (ruff, mypy).

## Как пишется код

- **Код пишет Claude**; внешние CLI-агенты не используются (D-37). Приёмка — одна для любого кода, регламент выше.
- Объёмное чтение (прочёс логов, сверка множества файлов, поиск по кодовой базе) можно уводить в сабагентов Claude, чтобы не раздувать основной контекст. Их вывод — мнение, а не истина: проверять перед тем, как на него опираться.
